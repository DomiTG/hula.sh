# Avionify

> The project that changed how I approach software architecture.

---

## Where it started

Avionify started with a simple question.

**What if every virtual airline, every pilot and every flight existed in one shared world instead of isolated servers?**

Most flight simulation platforms solve only one part of the experience. Some focus on virtual airlines, others on careers, while many leave the economy and progression entirely to spreadsheets or Discord servers.

I wanted to build a single platform where those pieces naturally fit together.

## Building the platform

From the beginning, the goal wasn't to create another website.

It was to build an ecosystem.

Pilots could progress through their careers, earn new aircraft type ratings and eventually join airlines operated by other players. Airlines managed their own fleets, recruited pilots and expanded over time, while everything happened inside the same persistent environment instead of separate communities.

As development continued, the project grew far beyond what I had originally planned.

Authentication, permissions, media management, real-time notifications, APIs, infrastructure and deployment all became part of the platform.

## Lessons learned

Avionify was the first project where architecture became more important than writing features.

As the codebase expanded, I started recognising decisions that made future development harder than it needed to be. Nothing was fundamentally broken, but I realised I was solving problems created by my own architecture instead of building new functionality.

That experience completely changed how I think about software design.

---

## Starting over

Eventually I reached a point where adding more code no longer felt like the right decision.

Instead of continuing to evolve the existing project, I archived Avionify and started again with a clean architecture.

That new project became **Flyv**.

The decision wasn't about abandoning the work that had already been done. Quite the opposite.

Without Avionify, Flyv wouldn't exist.

Nearly every architectural decision in Flyv is based on something I learned while building Avionify.

---

## Looking back

Although the project is now archived, I still consider it one of the most important things I've built.

It was my first large-scale web application, the first project where I had to think seriously about scalability and maintainability, and the point where I stopped seeing software as individual pages and APIs and started thinking in terms of systems.

In hindsight, archiving Avionify was probably the best technical decision I made.
